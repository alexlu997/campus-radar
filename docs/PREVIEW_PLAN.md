# 校园雷达 macOS 预览版实施计划

日期：2026-10-28。状态：用户已要求设置 Goal 并完成五阶段，Goal 为 active；P1–P4 已通过，P5 发布已完成，七个实际使用日观察中。

本计划承接当前功能核对，目标是修复已有来源的信息遗漏，并形成别人能够在 macOS 上安装、使用和卸载的 DSH 插件。顺序为简报修复、采集补齐与原文复查、完整打包、安装验收、发布准备与实际使用观察。

用户已要求“针对这五个阶段，设置 goal 并完成”，据此执行本计划并持续记录证据。用户已确定 Apache-2.0 许可证及公开仓库 alexlu997/campus-radar，现有 GitHub 登录有效；先完成可审阅的候选产物，再解决发布所需的具体决定。

## 依据与取舍

- 已复现：11 条有效新活动中，首日简报选择 10 条，次日剩余 1 条不再符合“新发现”条件，候选数为 0；完整列表仍有 11 条。需要修复未入选内容的顺延。
- 官网默认每源每次最多检查 12 篇、2 页。固定读取最新列表不能保证停机后的补齐，也不能持续发现退出该范围的旧文章变更。
- 当前插件包位于 `plugin/`，Python 核心位于包外；启动依赖预先配置的本机绝对路径。后台调度使用 macOS launchd。
- ME 砺远学术只验证过最新一篇正文路径，之后出现上游限流。首发将其作为可选能力，明确保留历史回补、限流恢复、授权有效期等限制；现有用户的启用状态与授权不因打包而被重置。

先提高现有三类官网来源的完整性，再扩大来源数量。发行采用同一仓库中的一个完整 DSH 组合包，包含 JavaScript 入口、Python 核心与公开来源配置，避免维护两套发布版本。首发以 macOS 预览版为目标；界面沿用现有样式。

## P1 修复简报候选顺延

状态：专项通过，最终完整回归 118 项 Python、11 项插件检查通过。

工作范围：`campus_radar/digest.py`、必要的存储查询、`tests/test_phase2.py`。优先复用已有每日简报快照判断活动是否入选；只有现有记录无法满足正确性时才增加状态字段。

- 未入选且仍符合条件的活动可以顺延到后续简报。
- 已入选活动不反复充当“新发现”；重要变更与临近截止仍可以按现有规则再次提醒。
- 保留明确反馈、活动状态、合并后的稳定 ID、当日重生成和历史快照行为。

验收：

1. 11 条有效新活动，首日选 10 条，次日选剩余 1 条；无新增或变更时，第三日不重复推送这批“新发现”。
2. 已结束、取消、不感兴趣或已经知道的内容按原有规则处理；重要变更与截止提醒没有被顺延修复屏蔽。
3. 当日重生成、跨源合并、旧简报读取和数据库重开不会丢失待选内容或产生重复活动。

## P2 补齐官网采集并复查仍有效的原文

状态：专项及有边界的真实官网验收通过。

工作范围：`campus_radar/collector.py`、`updates.py`、必要的存储状态与覆盖报告，及对应采集、更新测试。CLI、DSH 和定时更新继续共用业务入口。

- 在明确请求预算内保存补扫进度，后续更新可继续补齐。新发布导致分页移动时，通过重叠读取和 URL 去重避免漏项；不以简单放大抓取上限代替补齐逻辑。
- 区分本次请求成功、预算用尽、待补扫、已覆盖到已知边界和真正失败；未完成补齐时，不报告完整覆盖。
- 定期复查未结束或未截止活动的关联原文，优先处理仍有效的收藏项。时间未知的近期文档采用明确且可说明的复查窗口，不推断其已经结束。
- 原文变更保留证据；访问失败、404 或验证页不自动解释为活动取消。保持限速、TLS 校验、失败保留旧记录和重复触发保护。

验收：

1. 固定样本包含 35 篇分布在 5 页的文章，单次仍受 12 篇、2 页限制；多轮续跑后获得 35/35，重复入库为 0。
2. 补扫中途退出、单篇失败、页面新增和置顶重复链接均有针对性用例；失败项可恢复且覆盖状态准确。
3. 一篇已退出最新列表范围、但活动仍有效的文章更改时间、地点或取消状态后，能够检出变更并保留收藏、反馈与原文证据。
4. 对三个官网各做一次有边界的真实采集及重跑，记录实际页数、详情数、停止原因和待补扫范围；重跑无重复活动。

## P3 整理可安装的 macOS 组合包

状态：完整安装包已生成，文件清单与独立安装通过。

工作范围：根目录包清单、`plugin/`、Python 依赖声明、必要的初始化入口、运行目录定位、安装与卸载文档。复用现有 Python、SQLite、DSH 和 launchd 结构。

- 让安装包包含运行所需的插件代码、Python 核心与来源配置，并显式限定分发文件。
- 自动定位随包附带的代码；数据库与运行文件使用用户数据目录，去除对开发者用户名、仓库路径和旧虚拟环境的依赖。
- 声明实际验证的 Python、依赖和 DSH 版本；缺少运行条件时提供具体诊断和明确安装步骤，不通过安装插件隐式执行不可见的环境改造。
- 新安装默认使用三个官网来源；公众号需用户单独配置本机授权后启用。既有数据、收藏、反馈和来源选择在升级时保留。
- 后台任务提供明确的启用、停用和卸载方式；卸载插件后没有遗留采集进程或触发器，默认保留用户数据库。

验收：

1. 从打包产物的文件清单确认运行文件齐全；个人数据库、Cookie、二维码、授权文件、缓存及本机日志均不进入发行包。
2. 从仓库之外的安装目录运行，不引用开发仓库或开发者绝对路径。
3. 缺 Python、缺依赖、无微信授权、升级遇到已有数据库时，分别得到可操作的结果；已有数据不被覆盖或清空。
4. README 的版本、支持范围和安装方式与产物一致。GitHub 直接安装和本地 `.tgz` 的说明遵循同一包结构。

3. 验证后台到点更新、DSH 退出后执行、延迟启动补跑及与手动更新重叠时不重复运行。
4. 验证升级保留状态、停用、卸载、重新安装；清理本次测试触发器和进程。
5. 运行完整 Python 与插件检查，再完成真实宿主操作；自动检查通过不替代网络、安装与原生 DSH 验收。

## 本轮不扩展的功能

Windows／Linux、云服务、全网搜索、新来源批量接入、海报 OCR、附件解析、系统推送、复杂推荐及 UI 视觉重做暂不纳入本计划。公众号历史回补仍需先有可验证的获取路径，不承诺通过增加请求频率解决。

用户明确要求扩大来源、OCR、系统推送和复杂推荐在这五阶段完成后进行。当前 Goal 先完成五阶段，后续工作不提前混入；其他平台与 UI 视觉重做仍不在当前范围。
